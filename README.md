# Intelligent Workout Planner (KRR-Based)

A **Knowledge Representation & Reasoning (KRR)** workout planner that generates personalized weekly plans using pyDatalog. It fetches exercise data from the ExerciseDB API and includes a web chat application where an LLM updates user state, queries a database, and runs `pyDatalog` constraints to generate safe recommendations. The CLI flow respects user injuries, uses a 5-day split, and adjusts intensity from soreness feedback; data can be stored in Excel (users, plans, feedback) or SQLite for the web app.

## Run

### Fetch Exercises

From the project root:

```bash
python main.py
```

This creates/loads a user, generates the next week's plan, prints it with KRR reasoning per day, and optionally prompts for feedback (how was the week 1–5, soreness 1–5). Intensity for the next week is updated from **soreness** (high soreness → lower intensity, low soreness → higher intensity).

### Run the Chat Web Application

Start the web app from project root:

```bash
python web_main.py
```

Then open:

```
http://127.0.0.1:8000
```

What this web app does:
- Presents a chat-first interface
- Sends user messages to an LLM intent parser
- Persists user profile/constraints in SQLite (`data/workout_planner.db`)
- Uses `pyDatalog` rules to block unsafe exercises for injuries
- Returns recommendations and weekly plans based on DB + rules

## 5-Day Split

| Day | Focus           |
|-----|-----------------|
| 1   | Chest           |
| 2   | Back            |
| 3   | Legs            |
| 4   | Biceps/Triceps  |
| 5   | Shoulders       |

Each day has warmup, 4–6 exercises (filtered by that day's target muscles), and cooldown. Only **beginner** exercises are recommended; any exercise that trains a muscle in the user's `injury_muscles` is **forbidden**.

## Intensity (1–5)

- Stored per user as `current_intensity_level` (1–5).
- **Updated from soreness only** (not from "how was this week?" or completion):
  - **Soreness 4–5** → decrease level by 1 (min 1).
  - **Soreness 1–2** → increase level by 1 (max 5).
  - **Soreness 3** → no change.
- Intensity affects each exercise in the plan:
  - **Weight:** base weight × multiplier (0.5 at L1 → 1.0 at L5).
  - **Sets:** base sets + extra at higher levels (up to 5 sets).
  - **Reps:** base reps minus 2 per level (e.g. 12 → 4 from L1 to L5), min 4.

Base weights come from the exercise DB when present; otherwise they are estimated from exercise name and target muscle (see `models/exercise.py`).

## KRR (Knowledge Base)

**Facts (from data):**

- `is_exercise(E)` — E is in the exercise DB.
- `trains_muscle(E, M)` — exercise E targets muscle M (primary or secondary).
- `has_difficulty(E, D)` — E has difficulty D (e.g. `beginner`).
- `injured_muscle(User, M)` — user has M in their injury list.

**Rules:**

- `forbidden(User, E)` ← `trains_muscle(E, M)` ∧ `injured_muscle(User, M)`  
  (exercise is forbidden if it trains any injured muscle).
- `recommended(User, E)` ← `is_exercise(E)` ∧ `has_difficulty(E, beginner)` ∧ ¬`forbidden(User, E)`.

**Usage:** The planner queries `recommended(user_id, E)`, then filters results by the day's theme (e.g. chest, back). For each day, a short **KRR reasoning** block is printed: Facts, Rules, and Inference (query + result, or ∅ and explanation if rest day).

## API (main usage)

- **User:**  
  `get_or_create_user(user_id, name=..., age=..., weight=..., experience_level="beginner", injury_muscles=[], current_intensity_level=1)`  
  `get_user(user_id)`
- **Plan:**  
  `generate_next_week(user_id)` — returns plan dict, writes to `weekly_plans.xlsx`. Uses `user.current_intensity_level` and KRR to choose exercises.
- **Feedback:**  
  `save_feedback(user_id, week_number, feedback_score, soreness_level)`  
  `update_intensity_from_feedback(user_id, soreness_level)` — adjusts intensity from soreness (called after saving feedback).

## Data Files

- **users.xlsx:** `user_id`, `name`, `age`, `weight`, `experience_level`, `injury_muscles` (comma-separated), `current_intensity_level`.
- **weekly_plans.xlsx:** `user_id`, `week_number`, `day`, `exercise_name`, `sets`, `reps`, `weight`, `timestamp`.
- **feedback.xlsx:** `user_id`, `week_number`, `feedback_score`, `soreness_level`, `timestamp`.

`data/exercises_db.xlsx` must exist (for the CLI flow) and contain at least columns such as `name`, `target`, `difficulty` (and optionally `secondaryMuscles`, warmup/cooldown, etc.). The planner only recommends exercises with difficulty `beginner`. For the web app, `data/exercises_db.json` is used as the exercise seed; run the fetch flow to generate it.

### Output Files (data/ and config/)

- `exercises_db.json` — Raw exercise data in JSON format
- `exercises_db.xlsx` — Exercise data in Excel with serial numbers
- `workout_planner.db` — SQLite database used by the chat web app
- `config/offset_config.json` — Tracks last fetched offset and timestamp
- `config/rate_limit.json` — Tracks API request timestamps for rate limiting

### Core Functionality

- **API Integration**: Fetches exercises from ExerciseDB API via RapidAPI
- **Pagination**: Automatically handles pagination (10 exercises per API request)
- **Persistent Offset Tracking**: Remembers last fetched position to avoid duplicates across runs
- **Rate Limiting**: Enforces 1000 requests/hour limit with automatic cooldown
- **Duplicate Prevention**: Removes duplicates based on exercise `id` primary key
- **Data Appending**: Appends new exercises to existing files without overwriting
- **Web Chat Interface**: FastAPI + browser chat UI for interactive planning
- **LLM Integration**: LLM parses user requests into profile updates, exercise queries, and plan generation intents
- **Rule-Based Safety Engine**: `pyDatalog` enforces injury constraints against targets, secondary muscles, and body parts

### Data Storage

- **JSON Format**: Saves raw exercise data in JSON format
- **Excel Format**: Saves data in Excel with serial numbers for easy reference
- **SQLite Database**: Stores exercises and persistent per-session user profiles for chat planning
- **Column Flattening**: Automatically flattens nested arrays (e.g., `secondaryMuscles`) for Excel readability

### Troubleshooting

- **API key:** Ensure `EXERCISE_API_KEY` is set in `.env`; verify RapidAPI subscription.
- **Web chat / LLM:** Ensure `OPENAI_API_KEY` is set; verify `data/exercises_db.json` exists before `python web_main.py`. Without OpenAI key, a deterministic fallback parser is used.
- **Rate limit:** Wait for cooldown shown in console; request history is cleaned automatically.
- **Duplicates:** Prevented by exercise `id`; use `reset_offset(0)` to start fresh if needed.
- **File not found:** Ensure `data/` and `config/` exist and have write access.
